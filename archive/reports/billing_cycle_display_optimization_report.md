# 計費明細顯示優化報告

## 優化概述
根據用戶反馈，計費明細太多太亂，需要回到原本的整合顯示方式，並改善標註格式。

## 主要修正

### 1. 計費明細整合
- **問題**：原本每個收費週期都單獨顯示一行，導致明細過多
- **解決方案**：新增 `consolidate_billing_cycles()` 方法，將相同時段和費率的週期合併顯示
- **效果**：大幅減少明細行數，提高可讀性

### 2. 標註方式改善
- **舊格式**：`06-20 21:52-22:22`
- **新格式**：`{時間區段}{節假日類型}` 
  - 同日：`06-20 日間平日 (14:22-22:22)`
  - 跨日：`06-20~06-21 夜間平日 (22:22-09:22)`
  - 假日：`06-21 日間假日 (10:15-12:45)`

### 3. 代碼實現

#### 新增整合方法
```python
def consolidate_billing_cycles(
    self, billing_cycles: List[Dict], date_category: str
) -> Tuple[List[Dict], str]:
    """
    整合計費週期，將相同時段和費率的週期合併顯示
    使用 {時間區段}{節假日類型} 的標註方式
    """
```

#### 顯示格式改善
- 按時段名稱和費率分組
- 累加相同組別的時間和費用
- 生成統一的時間範圍顯示
- 使用新的標註格式

### 顯示效果對比

**修正前**（冗長）：
```
1. 06-20 21:52-22:22 - 30分鐘 × 30元/30分鐘 = 30元
2. 06-20 22:22-23:22 - 60分鐘 × 10元/60分鐘 = 10元
3. 06-20 23:22-00:22 - 60分鐘 × 10元/60分鐘 = 10元
...（多行）
```

**修正後**（簡潔）：
```
1. 06-20~06-21 日間平日 (21:52-08:30) - 38分鐘 × 30元/30分鐘 = 60元
2. 06-20~06-21 夜間平日 (22:22-08:22) - 600分鐘 (10小時) × 10元/60分鐘 = 100元
```

## 技術細節

### 整合邏輯
1. 按時段名稱和費率描述分組
2. 累加同組的時間和費用
3. 計算整體時間範圍
4. 生成統一的標註格式

### 標註規則
- **時段標識**：日間、夜間、全天
- **日期類型**：平日、假日、統一
- **時間格式**：
  - 同日：`MM-DD 時段類型 (HH:MM-HH:MM)`
  - 跨日：`MM-DD~MM-DD 時段類型 (HH:MM-HH:MM)`
