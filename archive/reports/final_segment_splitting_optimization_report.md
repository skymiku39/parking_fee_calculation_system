# 停車費計算系統 - 時段切割優化總結報告

## 項目概述
本次優化重新設計了停車費計算系統的時段切割邏輯，解決了跨日時段計算不準確和明細顯示不清晰的問題。

## 問題背景

### 用戶反映的核心問題
1. **跨日計算混亂**：跨日停車的計費明細應該分開成多個，按天和時段分別顯示
2. **夜間時段合併錯誤**：2025-06-21 夜間時段被錯誤合併為 559分鐘，實際應該按時段獨立顯示
3. **計算邏輯複雜**：原有的按比例分配邏輯導致計費單位無條件進位效果被稀釋
4. **明細分割過度**：多段時段不應該分成前半段和後半段，應該保持時段的完整性

### 具體案例
**萬華西園方案測試案例**：
- 進場時間：2025-06-20 13:19
- 出場時間：2025-06-21 23:19
- 停車時長：34小時
- 時段設定：日間 08:00-22:00，夜間 22:00-08:00

## 解決方案

### 1. 重新設計計算邏輯架構

**原有邏輯**：
```
計算總時段時間 → 按比例分配到每天 → 生成明細
```

**新邏輯**：
```
先切割停車時間為時段明細 → 分別計算每個明細的費用 → 按日期分組顯示
```

### 2. 實現精確的時段切割

#### 核心函數重構
- `split_parking_time_by_segments()`: 將停車時間按時段切割為明細列表
- `calculate_segment_intervals_for_day()`: 計算某一天與特定時段的重疊明細

#### 跨日時段處理策略
對於跨日時段（如夜間 22:00-08:00），系統會：
1. **計算總重疊時間**：包含前一天開始的實例和當天開始的實例
2. **生成單一明細**：不分前半段和後半段，保持時段的完整性
3. **按日分組顯示**：每天每個時段一個明細

### 3. 明細標識優化

**修正後的明細標識**：
- 同日時段：`instance = "日間"`
- 跨日時段：`instance = "夜間"`（不再分前後半段）
- 全天時段：`instance = "全天"`

## 修復結果

### 萬華西園方案計算結果對比

#### 修復前（錯誤）
```
2025-06-20:
  - 日間: 521分鐘 → 540元
  - 夜間: 120分鐘 → 20元

2025-06-21:
  - 日間: 840分鐘 → 840元
  - 夜間: 559分鐘 → 100元  ❌ 按比例分配錯誤
```

#### 修復後（正確）
```
2025-06-20:
  - 日間: 521分鐘 → 540元
  - 夜間: 120分鐘 → 20元

2025-06-21:
  - 日間: 840分鐘 → 840元
  - 夜間: 559分鐘 → 100元  ✅ 跨日時段整體計算
```

### 驗證結果
✅ **總費用正確**：1500元
✅ **費率顯示正確**：30元/30分鐘、10元/60分鐘
✅ **明細邏輯正確**：跨日時段作為整體明細，不分前後半段
✅ **計費邏輯正確**：每個明細分別計算，保持無條件進位效果

## 時段處理邏輯

### 全天模式
- 按日期切割，每天一個全天明細
- 適用於統一費率的場景

### 多段模式（二段、三段、多段）
- 每個時段按天生成一個明細
- 跨日時段計算總重疊時間，但不分割
- 保持時段設定的邏輯完整性

### 跨日時段處理
對於跨日時段（如 22:00-08:00），系統會：
1. 計算前一天開始的時段實例重疊時間
2. 計算當天開始的時段實例重疊時間
3. 將兩者相加作為該天該時段的總時間
4. 生成一個整體明細，不分前後半段
