# 智能計費週期合併優化報告

## 優化背景

用戶反饋原有的計費明細顯示方式存在以下問題：
1. **明細過多過亂**：每個收費週期都單獨顯示，導致明細行數過多
2. **錯誤的合併邏輯**：之前的合併方案會將不連續的時間段錯誤合併
3. **丟失邊界信息**：合併後失去了收費週期的真實邊界信息

## 智能合併方案

### 核心原則
- **時間連續性**：只合併時間上真正連續的週期
- **費率一致性**：只合併使用相同費率的週期
- **邊界保護**：不同時段之間絕不合併

### 合併邏輯
```python
def consolidate_billing_cycles(billing_cycles, date_category):
    """
    智能合併：只合併時間連續且費率相同的週期
    """
    # 1. 按時間順序排序
    sorted_cycles = sorted(billing_cycles, key=lambda x: x["start_time"])
    
    # 2. 逐個檢查是否可合併
    for cycle in sorted_cycles:
        if (current_group["end_time"] == cycle["start_time"] and 
            current_group["segment_name"] == cycle["segment_name"] and
            current_group["rate_description"] == cycle["rate_description"]):
            # 可以合併
            merge_cycles()
        else:
            # 不能合併，開始新組
            start_new_group()
```

### 合併條件
1. **時間連續**：`前一週期結束時間 == 當前週期開始時間`
2. **時段相同**：`segment_name` 相同
3. **費率相同**：`rate_description` 相同

## 測試結果驗證

**停車時間**：2025-06-20 21:52 - 2025-06-21 08:30

**合併結果**：

```
3. 06-21 日間平日 (08:22-08:30) - 8分鐘 × 30元/30分鐘 = 30元
```

**分析**：
- ✅ 第一個日間週期保持獨立（因為後面是夜間）
- ✅ 多個夜間週期智能合併（時間連續且費率相同）
- ✅ 最後的日間週期保持獨立（因為前面是夜間）
- ✅ 跨日標註正確顯示

### 測試場景4：假日費率

## 標註格式優化

### 新標註規則
- **格式**：`{日期} {時間區段}{節假日類型} (時間範圍)`
- **同日**：`06-20 日間平日 (14:22-22:22)`
- **跨日**：`06-20~06-21 夜間平日 (22:22-09:22)`
- **假日**：`06-21 日間假日 (10:15-12:45)`

### 標註優勢
1. **信息完整**：包含日期、時段、節假日類型、時間範圍
2. **格式統一**：所有場景使用一致的標註格式
3. **易於理解**：用戶一眼就能看懂時段和費率類型
