# 停車費計算系統架構優化報告

**報告日期：** 2024-12-19  
**優化類型：** 架構邏輯簡化  
**優化範圍：** 假日適用性設定層級  

---

## 📋 優化背景

### 問題發現

用戶提出了一個重要的架構邏輯問題：

> 在時段設定模式中，理論上是否適用於假日不需要出現，因為是否適用於假日已經包含在內了。

### 問題分析

原有的系統架構中存在**邏輯重複**：

1. **方案層級**有 `apply_on_holiday: bool` 設定
2. **時段層級**也有 `apply_on_holiday: bool` 設定

這種設計產生了以下問題：
- **邏輯混淆**：兩個層級都控制假日適用性
- **配置冗餘**：時段層級的設定在邏輯上是多餘的
- **維護困難**：需要同時管理兩個層級的假日設定

---

## 🎯 優化目標

### 核心邏輯釐清

**方案層級控制整體適用性**：
- 如果方案設定 `apply_on_holiday: false`，該方案不會在假日被選中
- 如果方案設定 `apply_on_holiday: true`，該方案可以在假日使用

**時段層級專注於費率調整**：
- 時段應該專注於費率計算邏輯
- 假日適用性已經在方案選擇階段決定
- 時段層級的 `apply_on_holiday` 設定變成多餘

---

## 🔧 實施的優化

### 1. 資料結構優化

#### 修改前：
```python
@dataclass
class TimeSlot:
    # ... 其他欄位 ...
    apply_on_holiday: bool = True  # ❌ 多餘的設定
    apply_on_festival: bool = True
    holiday_rate_multiplier: float = 1.0
    festival_rate_multiplier: float = 1.0
```

#### 修改後：
```python
@dataclass
class TimeSlot:
    # ... 其他欄位 ...
    # apply_on_holiday: bool = True  # ✅ 已移除
    apply_on_festival: bool = True  # 保留，因為可能有特殊需求
    holiday_rate_multiplier: float = 1.0
    festival_rate_multiplier: float = 1.0
```

### 2. 計算邏輯優化

#### 修改前：
```python
if date_type == "holiday":
    # 檢查時段是否適用於假日
    if time_slot.apply_on_holiday:  # ❌ 多餘的檢查
        rate_multiplier = time_slot.holiday_rate_multiplier
        date_type_description = "假日"
```

#### 修改後：
```python
if date_type == "holiday":
    # 假日費率（方案層級已經控制了適用性，所以直接應用）
    rate_multiplier = time_slot.holiday_rate_multiplier  # ✅ 直接應用
    date_type_description = "假日"
```

### 3. 配置文件清理

移除配置文件中時段層級的 `apply_on_holiday` 設定：

```json
{
  "time_slot_id": "day",
  "label": "假日日間",
  // "apply_on_holiday": true,  // ✅ 已移除
  "apply_on_festival": true,     // ✅ 保留
  "holiday_rate_multiplier": 1.2
}
```

## 🔮 保留的設計考量

### 為什麼保留 `apply_on_festival`？

節慶日的處理比假日更複雜，可能需要時段層級的精細控制：

1. **特殊時段需求**：某些時段在節慶日可能需要特殊處理
2. **彈性調整**：不同時段可能有不同的節慶費率策略
3. **業務需求**：實際營運中可能需要這種彈性

因此保留時段層級的 `apply_on_festival` 設定。
