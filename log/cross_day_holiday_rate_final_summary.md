## 🎯 問題概述

用戶發現停車費計算系統存在嚴重邏輯錯誤：

> **用戶反饋**：「6/21是日間假日吧? 2025/06/21 是週六」

**問題場景**：
- 進場時間：2025-06-20 15:48（週五）
- 出場時間：2025-06-21 17:48（週六）
- 問題：系統將週六也識別為平日，沒有使用假日費率

---

## 🔍 根本原因分析

### 技術原因
系統在 `determine_date_category` 函數中只使用**進場時間**來判斷整個停車期間的日期類別：

```python
# 錯誤邏輯
date_category = self.determine_date_category(enter_time, plan_data["holiday_type"])
# 整個26小時的停車期間都使用這個固定的"平日"類別
```

### 業務影響
- 跨日停車的假日時段被錯誤收費
- 假日費率功能失效
- 用戶權益受損（應該收更高的假日費率）

---

## 🛠️ 技術修正方案

### 1. 動態日期類別判斷
**修正前**：
```python
# 固定使用進場時間的日期類別
date_category = self.determine_date_category(enter_time, holiday_type)
segment_key = f"{segment_name}_{date_category}"
```

**修正後**：
```python
# 為每個收費週期動態判斷日期類別
current_date_category = self.determine_date_category(current_time, holiday_type)
segment_key = f"{current_segment['name']}_{current_date_category}"
```

### 2. 智能週期合併優化
**修正前**：
```python
# 只檢查時間連續性和費率相同
if (current_group["end_time"] == cycle["start_time"] and 
    current_group["rate_description"] == cycle["rate_description"]):
```

**修正後**：
```python
# 加入日期類別檢查
if (current_group["end_time"] == cycle["start_time"] and 
    current_group["rate_description"] == cycle["rate_description"] and
    current_group["date_category"] == cycle_date_category):
```

### 3. 準確的標籤顯示
**修正前**：
```
06-21 日間平日 (08:18-17:48)  # 錯誤標籤
```

**修正後**：
```
06-21 日間假日 (08:18-17:48)  # 正確標籤
```
