# 停車費計算系統 - 日期顯示修復報告

## 問題描述

用戶反饋計費明細中的日間時段缺少日期顯示，導致跨日停車時無法清楚區分不同日期的時段。

### 問題案例
- 進場時間：2025/06/20 下午 02:07
- 出場時間：2025/06/21 下午 04:07
- 停車時長：26小時

### 問題現象
計費明細顯示：
```
06-20~06-21 夜間 (22:00-08:00): 600分鐘 (10小時) | 100元
日間 14:07-22:00: 473分鐘 (7小時53分) | 480元  ❌ 缺少日期
日間 08:00-16:07: 487分鐘 (8小時7分) | 510元  ❌ 缺少日期
```

用戶無法區分兩個「日間」時段分別屬於哪一天。

## 技術分析

### 根本原因
在 `calculate_detailed_fee` 方法中，一般時段的 `time_range` 顯示格式為：
```python
"time_range": f"{segment_name} {interval['time_range']}"
```

這個格式缺少日期信息，而跨日時段有特殊處理包含日期範圍。

### 數據結構分析
- `interval["date"]` 字段存儲為字符串格式 `"YYYY-MM-DD"`
- 需要轉換為日期對象才能格式化為 `"MM-DD"` 格式

## 修復方案

### 代碼修改
在 `app.py` 的 `calculate_detailed_fee` 方法中，修改一般時段的顯示邏輯：

```python
# 修復前
fee_details.append({
    "time_range": f"{segment_name} {interval['time_range']}"
})

# 修復後  
# 生成帶日期的時段顯示
# interval["date"] 是字符串格式 "YYYY-MM-DD"，需要轉換成日期格式
date_obj = datetime.strptime(interval["date"], "%Y-%m-%d").date()
date_str = date_obj.strftime("%m-%d")
time_range_display = f"{date_str} {segment_name} {interval['time_range']}"

fee_details.append({
    "time_range": time_range_display
})
```

### 修復過程中的問題
1. **TypeError**: `'str' object has no attribute 'strftime'`
   - 原因：直接對字符串調用 `strftime` 方法
   - 解決：先將字符串轉換為 `datetime` 對象再格式化

## 技術細節

### 日期格式化
- 輸入格式：`"2025-06-20"` (字符串)
- 輸出格式：`"06-20"` (MM-DD)
- 轉換方法：`datetime.strptime().date().strftime()`

### 時段類型處理
1. **一般時段**：添加日期前綴 `"06-20 日間 14:07-22:00"`
2. **跨日時段**：保持原有格式 `"06-20~06-21 夜間 (22:00-08:00)"`
